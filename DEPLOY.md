# Деплой фронтов

Локальный запуск — `README.md`. Здесь то, что отличает бой от разработки.
Бэкенд деплоится сам по себе, его правила — в его репозитории.

## Три деплоя, один сайт

```
domain.kz         →  apps/web     (Vercel)
admin.domain.kz   →  apps/admin   (Vercel)
api.domain.kz     →  бэкенд       (свой сервер, не Vercel)
```

**Два проекта в Vercel из одного репозитория**, а не два репозитория:
общий `packages/ui` иначе пришлось бы публиковать приватным npm-пакетом
и поднимать версию в двух местах на каждую правку кнопки. Vercel делит
по проектам, а не по репозиториям.

**Все три обязаны быть поддоменами одного домена.** На этом держится вход:
кука сессии ставится бэкендом на `.domain.kz` и покрывает все три, `SameSite`
остаётся `Lax` и ослаблять его не нужно. Развести приложения по разным
доменам — значит остаться без входа, и чинится это уже не настройкой.

Имя куки при этом у приложений **разное** — `sid` у кабинета учителя,
`sid_admin` у админки: сервер выбирает его по `Origin` запроса
(`ADMIN_ORIGINS` в настройках бэкенда). Поэтому в одном браузере
одновременно живут два входа — админом с одного номера и учителем с другого.

## Настройки проекта в Vercel

Одинаково для обоих, отличаются только выделенные строки.

| Настройка | `web` | `admin` |
|---|---|---|
| Root Directory | `apps/web` | `apps/admin` |
| Framework Preset | Next.js | Next.js |
| Install Command | по умолчанию | по умолчанию |
| Build Command | по умолчанию (`next build`) | по умолчанию |
| Ignored Build Step | `bash ../../scripts/vercel-ignore.sh web` | `bash ../../scripts/vercel-ignore.sh admin` |
| Домен | `domain.kz` | `admin.domain.kz` |

Два места, где Vercel нужно поправить руками:

- **Include source files outside of the Root Directory** — включено. Без
  этого сборка не увидит `packages/` и упадёт на первом импорте `@lms/ui`.
- **Тариф.** Hobby у Vercel некоммерческий, а курсы платные, — значит Pro.
  Счёт считается за участников команды, а не за проекты: два проекта
  не удваивают его.

### Ignored Build Step

`scripts/vercel-ignore.sh` — коммит, задевший только админку, пересобирает
только админку. Правка в `packages/` задевает оба приложения и пересобирает
оба; первый деплой собирается всегда.

Сравнение идёт с **последней удачной сборкой этого проекта**
(`VERCEL_GIT_PREVIOUS_SHA`, Vercel отдаёт её только внутрь Ignored Build Step),
а не с `HEAD^`. В пуше почти всегда несколько коммитов, и по `HEAD^` пропуск
считался по последнему из них: пуш, где последний коммит трогал только админку,
оставлял клиентское приложение на старой сборке вместе со всеми правками ниже.

Договорённость Vercel обратная привычной: выход `0` — сборку **пропустить**.

## Переменные окружения

`NEXT_PUBLIC_*` подставляются **в момент сборки**, а не читаются при запуске:
значение попадает прямо в js-файлы. Отсюда два следствия — задать их нужно
до первой сборки, а изменить их значит пересобрать, а не перезапустить.

| Переменная | `web` | `admin` | Что это |
|---|---|---|---|
| `NEXT_PUBLIC_API_URL` | `https://api.domain.kz` | `https://api.domain.kz` | единственная дорога на бэкенд (`packages/api/client.ts`) |
| `NEXT_PUBLIC_ADMIN_URL` | `https://admin.domain.kz` | — | ссылки в админку с клиентских экранов (`apps/web/lib/urls.ts`) |
| `NEXT_PUBLIC_WEB_URL` | — | `https://domain.kz` | ссылки на клиентские экраны из админки (`apps/admin/lib/urls.ts`) |

Те же три переменные с боевыми значениями лежат образцами рядом с самими
приложениями: `apps/web/.env.example` и `apps/admin/.env.example`.

Локально они не нужны вовсе: умолчания в коде — это `localhost:8000`,
`localhost:3001` и `localhost:3000`.

Секретов среди них нет и быть не может: всё, что с приставкой
`NEXT_PUBLIC_`, уезжает в браузер. Ключи, токены и пароли живут только
на бэкенде.

## Порядок первого выката

1. Бэкенд поднят и отвечает на `https://api.domain.kz/health` — иначе
   первый же экран фронта покажет ошибку сети.
2. `CORS_ORIGINS` на бэкенде содержит **оба** адреса фронтов, а
   `COOKIE_DOMAIN` — `.domain.kz`.
3. Оба проекта в Vercel заведены, Root Directory и переменные заданы.
4. Домены привязаны, DNS указывает на Vercel.
5. Проверить руками вход: `domain.kz/login` → код → `/me` отвечает.
   Не отвечает — смотреть куку в инструментах браузера: чаще всего это
   `COOKIE_DOMAIN` или `COOKIE_SECURE`.
6. Проверить, что стороны развязаны: войти в админку и убедиться, что вход
   в кабинете учителя остался живым. Выбило — на бэкенде не задан
   `ADMIN_ORIGINS`, и админка получила ту же куку, что и кабинет.

Отдельное ограничение первого выката, о котором нужно знать до раздачи
адреса людям: **настоящего SMS-провайдера у бэкенда нет**, код входа
печатается в его лог. Учитель войти не может — вход есть только у админа
(подробности в `DEPLOY.md` бэкенда). Каталог при этом виден всем: он
открытый и входа не требует.

## Проверки перед выкатом

```sh
npm run typecheck
npm run build
```

Сборка проверяет и типы, но `typecheck` отвечает быстрее и говорит понятнее.
Типы ответов API генерируются из OpenAPI-схемы бэкенда — разошедшийся
контракт всплывает здесь, а не на экране.
