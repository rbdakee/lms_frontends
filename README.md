# LMS для учителей — фронтенд

Два приложения и общая дизайн-система в одном репозитории.

```
apps/web/            каталог, кабинет учителя, уроки, сертификаты   →  domain.kz
apps/admin/          заявки, доступы, проверка работ, редакторы     →  admin.domain.kz
packages/ui/         кнопки, поля, иконки, словарь, globals.css
packages/api/        слой запросов к бэкенду и типы из OpenAPI-схемы
packages/prototype/  моки и состояние прототипа — временный пакет
```

## Запуск

```bash
npm install
npm run dev          # оба сразу: web :3000, admin :3001
npm run dev:web      # только клиентское приложение
npm run dev:admin    # только админка
```

Экраны входа, каталога, кабинета и заявок ходят в API — в dev он поднимается
командой `docker compose up --build` в `../backend` (адрес по умолчанию
`http://localhost:8000`, меняется переменной `NEXT_PUBLIC_API_URL`). SMS-код
при входе пишется в лог контейнера `api`.

Сборка: `npm run build` (оба) или `npm run build:web` / `npm run build:admin`.
Проверка типов: `npm run typecheck`. Типы ответов API генерируются из схемы
поднятого бэкенда: `npm run generate -w @lms/api` — руками их не правим.

## Почему два приложения, а не одно

Это разные системы по требованиям, а не два раздела одного сайта:

| | `apps/web` | `apps/admin` |
|---|---|---|
| Кто заходит | любой человек из интернета | несколько сотрудников |
| Что внутри | каталог, кабинет, уроки | ФИО и телефоны учителей, доступы, отчёты |
| Что нужно | индексация, скорость на слабом интернете | ничего из этого |
| Как закрывается | открыто по определению | свой домен, можно закрыть по IP или VPN |

Отсюда главное: **админский код не уезжает в браузер учителя**, а выкладка админки
не трогает каталог, который в это время собирает заявки. Проверяется это просто —
в CSS клиентского приложения нет ни одного правила `.admin-*`, а в его JS нет
админских данных.

Подробности и причина решения — `../BACKEND_NOTES.md`, раздел 1.

## Ссылки между приложениями

Приложения на разных доменах, поэтому ссылка «в соседнее» — не маршрут Next,
а полный адрес. Он строится в одном месте: `apps/web/lib/urls.ts` и
`apps/admin/lib/urls.ts`, домен берётся из `NEXT_PUBLIC_ADMIN_URL` и
`NEXT_PUBLIC_WEB_URL` (см. `.env.example` рядом). Без переменных работает
локальный запуск на соседних портах.

**«Предпросмотр как учитель»** стал переходом между приложениями: админка
открывает клиентское приложение с `?preview=1`, оно включает режим у себя,
показывает полосу «данные не сохраняются» и по выходу возвращает в админку.
Когда появится сервер, флаг переедет в сессию — `BACKEND_NOTES.md`, раздел 12.

## Состояние прототипа

`packages/prototype` — **временный пакет**: моки из `DESIGN_PROMPTS.md` и состояние
в `localStorage`. Он уезжает в API по сессиям из `../BACKEND_PLAN.md`, и к концу
восьмой сессии от него остаётся только язык, тосты и режим предпросмотра.

Вход, профиль, каталог, страница курса, «Мои курсы» и админские заявки уже
живут на API: связка «админ выдал доступ — курс появился у учителя» работает
по-настоящему. На моках остаются уроки и всё за ними (тесты, задания,
сертификаты, уведомления, админские редакторы) — до своих сессий.

Сбросить прототипные разделы: **Профиль → Управление прототипом** или `/map`.

## Что где лежит

```
apps/web/
  app/                 маршруты клиентской части
  components/          Shell, карточка курса, программа, плеер, сертификат
  lib/urls.ts          ссылки в админку
  lib/qr.ts            QR на сертификате
apps/admin/
  app/                 маршруты админки, без префикса /admin — домен и так свой
  components/admin/    заявки, выдача доступа, модерация, участники курса
  components/layout/   AdminShell
  lib/urls.ts          ссылки в клиентское приложение и предпросмотр
packages/ui/
  components.tsx       кнопки, поля, бейджи, модалки, скелетоны, пустые состояния
  icons.tsx            весь набор иконок
  i18n.ts              словарь RU / KZ и форматирование чисел, дат, цен
  useOrigin.ts         адрес, на котором открыт сайт — для ссылок проверки и QR
  globals.css          палитра, типографика, компоненты
  admin.css            каркас админки — подключает только apps/admin
packages/api/
  client.ts            обёртка над fetch: кука сессии, единый формат ошибки
  me.tsx               MeProvider — «кто вошёл» из GET /me
  useLoad.ts           загрузка / ошибка с повтором / данные
  dictionaries.ts      справочники: регионы, предметы, категории
  types.gen.ts         сгенерировано из /openapi.json — не редактировать
  types.ts             короткие имена поверх сгенерированного
packages/prototype/
  data.ts              тестовые данные
  store.tsx            состояние прототипа
  ToastHost.tsx        тосты — привязаны к стору, поэтому живут здесь
```

Общий пакет обязателен: два независимых репозитория означают две копии кнопки,
которые через полгода выглядят по-разному, и это замечает не разработчик,
а тот, кто смотрит на систему целиком.

## Деплой

Два проекта на Vercel из одного репозитория, у каждого свой **Root Directory**:
`apps/web` и `apps/admin`. Сборочная команда по умолчанию; в переменных окружения
проекта — адрес соседнего приложения. Админке в бою дополнительно закрывается
доступ по IP или через VPN: это самая дешёвая защита персональных данных, какая
есть, и она возможна только на отдельном домене.

## Прототип до разделения

Исходный однодомённый прототип остался в `../design_preview` и продолжает
работать как есть. Он заморожен: правки идут только сюда.
