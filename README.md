# LMS для учителей — фронтенд

Три приложения и общая дизайн-система в одном репозитории.

```
apps/web/            первая учебная площадка: каталог, кабинет, уроки  →  domain.kz
apps/web2/           вторая учебная площадка: те же экраны, свой бренд →  домен ждём
apps/admin/          заявки, доступы, проверка работ, редакторы        →  admin.domain.kz
packages/ui/         кнопки, поля, иконки, словарь, язык, тосты, globals.css
packages/api/        слой запросов к бэкенду и типы из OpenAPI-схемы
packages/course/     экраны курса глазами учителя — общие у кабинета и предпросмотра
packages/site/       общие экраны площадки: вход, онбординг, профиль, сертификаты
packages/prototype/  моки и состояние прототипа — временный пакет, остался у админки
```

## Запуск

```bash
npm install
npm run dev          # все три: web :3000, admin :3001, web2 :3002
npm run dev:web      # только первая площадка
npm run dev:admin    # только админка
npm run dev:web2     # только вторая площадка
```

Экраны входа, каталога, кабинета и заявок ходят в API — в dev он поднимается
командой `docker compose up --build` в `../backend` (адрес по умолчанию
`http://localhost:8000`, меняется переменной `NEXT_PUBLIC_API_URL`). SMS-код
при входе пишется в лог контейнера `api`.

Сборка: `npm run build` (все три) или `npm run build:web` / `npm run build:admin` /
`npm run build:web2`. Проверка типов: `npm run typecheck`. Типы ответов API
генерируются из схемы поднятого бэкенда: `npm run generate -w @lms/api` — руками
их не правим.

## Две учебные площадки

`apps/web` и `apps/web2` — два бренда на разных доменах, одна админка и один
бэкенд (`../PLATFORMS_BRIEF.md`). Экраны у них общие: обучение приходит из
`packages/course`, вход, онбординг, профиль, уведомления и сертификаты —
из `packages/site`, и оба пакета получают адреса, кадр и бренд **через хозяина**
(`CourseHost`, `SiteHost` в каждом приложении). Своё у площадки — `Shell`,
лендинг, каталог, кабинет и тема.

**Тема — переопределение токенов, а не второй `globals.css`.** Дизайн-система
одна: `packages/ui/globals.css` держит палитру, шкалу и плотность в `:root`,
а `apps/web2/app/theme.css` переопределяет значения. Копия дизайн-системы
запрещена договорённостью — понадобился непохожий компонент, он едет
в `packages/ui` вариантом.

**Площадку сервер узнаёт по `Origin`**, а не по переменной окружения: каталог,
доступы, прогресс, отзывы и сертификаты фильтруются на сервере. Аккаунт при этом
один — телефон, один человек, один `user`.

## Почему приложения разные, а не один сайт

Это разные системы по требованиям, а не два раздела одного сайта:

| | `apps/web` | `apps/admin` |
|---|---|---|
| Кто заходит | любой человек из интернета | несколько сотрудников |
| Что внутри | каталог, кабинет, уроки | ФИО и телефоны учителей, доступы, отчёты |
| Что нужно | индексация, скорость на слабом интернете | ничего из этого |
| Как закрывается | открыто по определению | свой домен, можно закрыть по IP или VPN |

Отсюда главное: **админский код не уезжает в браузер учителя**, а выкладка админки
не трогает каталог, который в это время собирает заявки. Проверяется это просто —
в CSS клиентского приложения нет ни одного правила `.admin-*`, а в его JS нет
админских данных.

Подробности и причина решения — `../BACKEND_NOTES.md`, раздел 1.

## Ссылки между приложениями

Приложения на разных доменах, поэтому ссылка «в соседнее» — не маршрут Next,
а полный адрес. Он строится в одном месте: `lib/urls.ts` каждого приложения,
домен берётся из `NEXT_PUBLIC_ADMIN_URL` и
`NEXT_PUBLIC_WEB_URL` (см. `.env.example` рядом). Без переменных работает
локальный запуск на соседних портах.

**«Предпросмотр как учитель»** живёт внутри админки — маршрут
`/preview/:courseId`. Домены никто не пересекает: экраны курса общие
(`packages/course`), режим включает layout предпросмотра запросом
`POST /admin/preview/enter`, а гасит его уход с маршрута. В режиме доступ
к курсу считается открытым, черновик виден, а записи не сохраняются: попытка
теста считается в памяти, сдача задания и отзыв до базы не доходят
(`BACKEND_NOTES.md`, раздел 12).

Предпросмотр **полный**: тест проходится, задание сдаётся, сертификат
показывается. Выходов наружу в нём нет — каталога, сертификатов и профиля
в админке не существует, и такие кнопки экраны не рисуют.

## Состояние прототипа

`packages/prototype` — **временный пакет**: моки из `DESIGN_PROMPTS.md` и состояние
в `localStorage`. Он уезжает в API по сессиям из `../BACKEND_PLAN.md`.

Клиентское приложение его больше не подключает вовсе: язык и тосты переехали
в `packages/ui` (они не про прототип), отзыв о курсе ушёл в `POST /courses/{id}/reviews`.
Пакет остался только у админки — админские редакторы и модерация отзывов,
до своих сессий бэкенда.

  lang.tsx             выбранный язык интерфейса
  toast.tsx            тосты и их провайдер

Общий пакет обязателен: два независимых репозитория означают две копии кнопки,
которые через полгода выглядят по-разному, и это замечает не разработчик,
а тот, кто смотрит на систему целиком.

## Деплой

Три проекта на Vercel из одного репозитория, у каждого свой **Root Directory**:
`apps/web`, `apps/web2` и `apps/admin`. Сборочная команда по умолчанию; в переменных окружения
проекта — адрес соседнего приложения. Админке в бою дополнительно закрывается
доступ по IP или через VPN: это самая дешёвая защита персональных данных, какая
есть, и она возможна только на отдельном домене.

Настройки проектов, переменные окружения и порядок первого выката — `DEPLOY.md`.

## Прототип до разделения

Исходный однодомённый прототип остался в `../design_preview` и продолжает
работать как есть. Он заморожен: правки идут только сюда.
