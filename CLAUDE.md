# Фронтенд — правила

Три приложения и общая дизайн-система. Как устроено и как запускается — `README.md` рядом.
Общие правила проекта — `../CLAUDE.md`, две площадки — `../PLATFORMS_BRIEF.md`.

## Три приложения, а не три раздела

`apps/web` и `apps/web2` — две учебные площадки на разных доменах и с разными
брендами, `apps/admin` → `admin.domain.kz` — одна админка на обе. Разные сборки,
разные деплои.

Ради чего разделяли: **админский код не уезжает в браузер учителя**, а выкладка админки
не трогает каталог, который в это время собирает заявки. Ломается это незаметно, поэтому:

- Экраны сторон друг друга не импортируют. Общее живёт в пакетах: `packages/ui` —
  дизайн-система, язык и тосты; `packages/course` — экраны курса глазами учителя,
  общие у кабинета и у предпросмотра в админке; `packages/site` — вход, онбординг,
  профиль, уведомления, сертификаты и проверка, общие у двух площадок. Копий этих
  экранов быть не должно.
- Экраны курса не знают, в каком они приложении: адреса и кадр им отдаёт хозяин
  через `@lms/course/host` (`CourseHost` в клиенте, `PreviewHost` в админке).
  Захардкоженный `/courses/12` внутри `packages/course` — ошибка.
- Проверка: в CSS клиентского приложения нет ни одного правила `.admin-*`, в его JS —
  ни одной админской мок-таблицы. Каркас админки живёт в `packages/ui/admin.css`
  и подключается только админкой.
- Админка не индексируется (`robots: { index: false }`) и в бою закрывается по IP или VPN.

## Вторая площадка отличается темой и брендом, а не копией

- **Тема — переопределение токенов.** `packages/ui/globals.css` держит палитру,
  шкалу и плотность в `:root`, `apps/web2/app/theme.css` переопределяет значения.
  Второго `globals.css` быть не может: правка кнопки обязана доезжать до обеих
  площадок. Понадобился непохожий компонент — он едет в `packages/ui` **вариантом**.
- **Бренд — свойство площадки.** Название и логотип лежат в `lib/brand.ts`
  приложения и приходят в общие пакеты через хост (`CourseHost`, `SiteHost`).
  Имя площадки в словаре `packages/ui/i18n.ts` или в общем экране — ошибка:
  им подписан сертификат, а документ выдают людям.
- **Площадку сервер узнаёт по `Origin`.** Переменной с кодом площадки на фронте
  нет и заводить её не нужно: каталог, доступы, прогресс и сертификаты
  фильтруются на сервере.

Маршруты админки идут **без префикса `/admin`** — домен у неё свой. Ссылка в соседнее
приложение — не маршрут Next, а полный адрес из `lib/urls.ts`
(`NEXT_PUBLIC_WEB_URL` / `NEXT_PUBLIC_ADMIN_URL`), а не строка в разметке.

## packages/prototype — временный

Моки и состояние в `localStorage`. Пакет уезжает в API по сессиям из `../BACKEND_PLAN.md`.
Клиентское приложение его **не подключает вовсе** — остался только у админки: админские
редакторы и модерация отзывов. Язык и тосты из него уехали в `packages/ui`.
**Не наращивать**: состояние, которому место в API, туда не добавляем — его придётся
выносить обратно.

Состояние у приложений **раздельное** — разные домены, разные хранилища. Демо-связка
«админ открыл доступ → курс появился у учителя» вернётся с настоящим API в третьей сессии;
распорки под неё не строим и в текстах экранов её не обещаем.

«Предпросмотр как учитель» — маршрут админки `/preview/:courseId`, домены он больше
не пересекает. Режим включает layout предпросмотра (`POST /admin/preview/enter`),
а гасит уход с маршрута. Предпросмотр полный: тест проходится, задание сдаётся,
и ничего из этого не сохраняется — за это отвечает сервер.

## Работа с бэкендом

Экраны подключаются к зафиксированным примерам ответов — они и есть контракт, и работаем
от них. В код `backend/` заглядываем, только когда пример не отвечает на вопрос, и только
на чтение.

Не хватает поля или не та форма — это **правка контракта**: собираем владельцу, а не
подгоняем экран под то, что вернулось.

У каждого экрана, который ходит за данными, есть три состояния: загрузка, ошибка сети
и пустой ответ. Пустые состояния уже нарисованы (`Empty` в `packages/ui`) — используем их,
а не придумываем новые.

## Тексты на экранах

Запрещены обещания бесплатности и охвата: никаких «бесплатно» и «для всех учителей
Казахстана». Интерфейс двуязычный (RU/KZ) — переводится обвязка, содержание курсов
остаётся на своём языке: курс одноязычный, версии живут отдельными курсами и связаны
`group_id`. Новые строки идут в словарь `packages/ui/i18n.ts`, а не в разметку.

## Перед сдачей

`npm run build` и `npm run typecheck` проходят во **всех трёх** приложениях.
Запуск: `npm run dev` — web на `:3000`, admin на `:3001`, web2 на `:3002`.

`../design_preview/` — прототип до разделения, заморожен: правки идут только сюда.
